## Findings and verified resolution

| ID | Priority | Finding and recommended correction |
| --- | --- | --- |
| RP-01 | P2 | Repetition counts are absent from table rows, and runs with unequal repetitions can share a panel. A synthetic repetition-1/repetition-2 fixture produced one primary panel. `compareRuns` rejects unequal repetitions and differing variants, whereas the report's general reading guidance names only split, dataset and harness. Show each row's repetition count and state that panel membership alone does not establish a clean paired comparison: matching task order, variant and repetitions, complete coverage and no observed truncation are also required. Raw configured-run observations should remain visible when truncated, with their warning; they must not imply an admissible paired contrast. |
| RP-02 | P2 | A run containing both development and holdout episodes receives the first episode's split label in the panel heading and row. A synthetic `dev` then `holdout` fixture rendered `dev panel`, although its score pooled both. Render the complete observed split set, explicitly label mixed coverage, or reject mixed-split primary selection. This is a caller-edge-case finding; no actual panel outcomes were inspected. |
| RP-03 | P3 | When every requested primary run ID is absent, the report says “No real provider runs recorded yet” even when supplied runs remain in the historical archive. A synthetic missing-ID fixture reproduced this. Use “No selected primary runs available” and expose missing requested IDs, without suppressing the archive. This empty-selection behavior predates the grouping change. |

All three findings are **resolved in the reviewed follow-up source**. RP-01: the grouping key now includes repetitions, each row shows attempts per case, and panel text explicitly says panel membership does not establish a clean comparison; truncation, incomplete coverage and condition caveats remain visible. RP-02: both row and panel labels use the complete sorted observed split set, including `dev + holdout`. RP-03: unavailable primary selections receive a specific empty-selection message plus an escaped missing-ID warning; recorded runs remain in the archive. The new regression test exercises all three corrections. Different variants remain visibly identified rows, rather than a claim that every row is an admissible paired contrast; comparison validation remains the responsibility of `compareRuns` and its caller.

No introduced HTML injection, dropped supplied run, or malformed new warning markup was found. These conclusions apply to the inspected text/attribute paths; no browser acceptance was performed as part of this source review. Prebuilt comparison objects remain a caller-controlled input: the report renders them rather than independently repeating `compareRuns` validation.
