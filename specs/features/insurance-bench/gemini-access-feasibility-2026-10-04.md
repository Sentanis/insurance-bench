## Core-only alternative: promising, version-pinned and unprobed

There is no separate installed `@google/gemini-cli-core` package at the CLI's dependency path. The CLI package publishes bundled files and no declared package `exports` API. Its `chunk-M6NSK26M.js` nevertheless exports `getOauthClient`, `CodeAssistServer`, `createCodeAssistContentGenerator` and `createContentGenerator`. Importing such a generated chunk would be an internal, version/hash-pinned integration, not a stable supported SDK interface.

The raw `CodeAssistServer.generateContent` method passes `req.model` through unchanged, translates explicit `maxOutputTokens`/thinking settings/tools/system instructions into the request, and returns native candidates, `usageMetadata`, `modelVersion` and prompt feedback. Candidate `finishReason` is retained. This method does not invoke CLI model selection, fallback handlers, repository context, memory discovery or a tool registry. An empty tool array and response-side rejection of unexpected function calls would keep model output from invoking external capabilities. Avoid the higher-level `createContentGenerator`, which adds model mapping and logging wrappers.

Initialization is the meaningful gate. The standard factory performs OAuth initialization plus `setupUser`; the latter can issue `onboardUser` if no existing current tier is found. OAuth initialization may refresh credentials, cache account information and launch login unless browser launch is suppressed and interaction is disabled. A proposed isolated adapter can use `getOauthClient` with minimal noninteractive/browser-suppressed configuration, call the raw server's `loadCodeAssist`, require an existing tier/project, and fail rather than onboard, select another account or initiate login. Programmatic transport credential loading must never print or persist identities/tokens in benchmark evidence.

The raw generator normally attempts to record conversation-offered metrics, but the inspected helper returns without sending those metrics unless a response contains an editing-tool call. Denying all tools and rejecting unexpected function calls are therefore important; a bounded request allow-list should additionally forbid onboarding, interaction/metrics writes and any other side-effect method. Its `requestPost` also defaults to three transport retries; a one-request probe must explicitly disable or bound retries and verify request counts rather than assume one method call means one HTTP attempt. Entitlement, endpoint model identity and any server-side routing remain unproven until a reserved probe returns native metadata.

## Bounded implementation and probe proposal

Implement any experiment in a **new isolated module**, leaving frozen shared providers/model definitions unchanged. The raw Code Assist path above is a conditional OAuth alternative requiring independent configuration, network-method isolation and native metadata verification. A supported direct native API adapter would provide explicit generation configuration, native finish reason/model version and usage metadata with fewer CLI-specific conditions, but no API key is currently established. Neither absence of that key nor internal integration instability establishes that Gemini access is unavailable.

Before a CLI-backed ability run, the new adapter must demonstrate: no inherited repository/global memory or agent capabilities; no MCP/extension/hook startup; no executed tool calls; exactly one permitted model across all model-use statistics; no classifier, helper or fallback calls; captured effective output cap; native or equivalently complete truncation evidence; an outer deadline; and usage/cost settlement even on error. CLI prompts/system scaffolding remain a distinct configured-system condition and must not be presented as a raw API model comparison. Treat missing model usage or finish reason as missing evidence, not as zero tokens or successful completion.

The next inference step is a **prospectively registered, budget-reserved, reviewed synthetic access probe**, not a benchmark task. The user's benchmark instruction and approved $75 total cap already authorize bounded synthetic inference using existing access; the current pause is an implementation-review workflow gate, not a request for new human permission. Specify one exact model, a tiny input, a common explicit output cap, one request/no fallback, and an outer deadline. Record sanitized model/configuration/usage/error evidence only. Stop on authentication, unavailable-model, mixed-model or unverifiable-output errors; do not change login, purchase access, silently substitute models, or admit a leaderboard score.

## Isolated implementation, awaiting review and access probe

The new `insurance-bench/gemini-code-assist.ts` uses only the version-pinned raw OAuth/Code Assist exports. All five files in the static import closure have explicit SHA-256 pins; unknown CLI version or altered/missing dependency fails before SDK import. Static source inspection found deferred OAuth initialization, no CLI Config/factory initialization on this route, and a global HTTP dispatcher initialization; SDK import therefore runs only inside a disposable muted child process. No SDK import or credential loading was executed during development tests.

The worker receives an empty environment, supplies no model tools, suppresses login/browser interaction, requires an existing tier/project, fixes the Google endpoint, allows only `loadCodeAssist` and `generateContent` POST methods, disables retries, and excludes CLI context/memory, fallback/helpers, MCP, shell, browser and tool registries. Requests accept either an access prompt or a native messages array, with mutual-exclusion and byte-limit checks. Explicit system content becomes `systemInstruction`; user and assistant history retains native `user`/`model` roles. Source text inside user/tool-result messages remains user content. Its output boundary exposes only validated completion/token fields or fixed error codes. Native `modelVersion` must exactly match the requested model, and observed output including thinking cannot exceed the declared cap. An outer 300-second kill deadline bounds authentication and inference as well as request-level cancellation. Existing credential refresh occurs only inside the authorized SDK path; credentials and identities are never adapter output.

The new `scripts/insurance-bench-gemini-probe.ts` defaults to public preflight booleans/pins without loading the SDK. Explicit dispatch uses the same `.tmp/insurance-bench/session-budget.json` and approved $75 total cap, a 2048-output-token access-only prompt, and 4096 input-token reservation headroom. Reservation uses the maximum configured rates ($2 input/$12 output per million) for either profile, giving a known-model substitution margin. It never resets the ledger. **Every failed admission retains the full reservation**, including failures with valid native usage; safe observed usage and a requested-rate estimate may be recorded with `billingUncertain: true`, without settling at an untrusted tariff. Only a successful admission settles a clearly labeled requested-model Developer API reference cost rather than claiming exact OAuth billing. Receipt output excludes the response body, account/project identity, auth URLs and provider error bodies. No ability score is produced.
